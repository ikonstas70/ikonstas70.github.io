Edge Defense

The first layer nothing gets past without passing through: automatic bot and attack-pattern mitigation at the network edge, in front of every service I run. Hostile and automated traffic gets challenged or blocked before it ever reaches origin infrastructure — origin servers only ever see traffic that's already cleared that filter. Behind the edge, a continuous file-integrity scanner watches for unauthorized change across the properties it fronts, feeding the same behavioral pipeline SENTINEL uses.

Host Security Stack

On the host itself: continuous file-integrity monitoring against a known-good baseline, an automated IP-blocklist pipeline fed by threat-intelligence sources and enriched over time, a hardened network posture that null-routes known tracking and advertising infrastructure at the resolver level, and a private, authenticated operations dashboard for watching all of it — never exposed to the open internet. Thousands of hostile sources are on the permanent blocklist at this point, and the last full integrity sweep came back clean.

Post-Quantum Cryptography

Google's March 2026 warning — later echoed by Cloudflare and backed by a $2B U.S. government emergency program — put a working estimate on the table: large-scale quantum computers capable of breaking today's public-key cryptography could arrive by 2029. "Harvest now, decrypt later" makes that a today problem, not a 2029 problem: encrypted traffic captured now can simply be stored and broken retroactively once the hardware exists.

The cryptographic layer protecting management channels across this stack implements NIST FIPS 203/204 directly — ML-KEM-768 for post-quantum key encapsulation and ML-DSA-65 for post-quantum signatures, combined with classical X25519 in a hybrid construction so an attacker has to break both simultaneously, even if one falls first. Full technical detail — parameter sizes, the six-vector attack simulation, signature verification — is in the SENTINEL writeup.

Encrypted Infrastructure Repos

Source and configuration for every site and service I run live in git-crypt AES-256 encrypted repositories, synced automatically on a fixed interval with continuous integrity verification. The threat model isn't just "don't leak this publicly" — it's that even private version-control storage shouldn't hold plaintext infrastructure secrets. Keys are held locally, protected by a passphrase, never committed alongside the content they protect.

Zero-Trust Homelab

Everything above runs across two nodes: a Mac Mini on-prem and an Oracle Cloud free-tier instance, joined over a WireGuard mesh. Neither node accepts a direct inbound connection from the internet — the only public entry point for anything is a Cloudflare Tunnel, which means there's no port to scan in the first place, on either side. It's the same "assume breach, verify everything" posture as the rest of the stack, just applied at the network-topology level instead of the application level.
