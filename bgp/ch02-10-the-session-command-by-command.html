The recorded session, one command at a time: the exact command, the real output, what you are looking at, and why it matters. Every command is read-only and works on the public login, so you can repeat each step yourself.

Session recorded 3 November 2026 on route-views.routeviews.org (username rviews). Start with terminal length 0. In commands 3, 7 and 8, each path's RPKI line is folded onto the path it belongs to.

Command 1 of 11

The size of the Internet and its RPKI posture

route-views> show ip bgp summary | include table version|RPKI|network entries|BGP using
BGP table version is 1517822914, main routing table version 1517822914
Path RPKI states: 11656636 valid, 4793762 not found, 5344 invalid
1129444 network entries using 280102112 bytes of memory
BGP using 3150829866 total bytes of memory

What you see. The table version counts every best-path change since BGP started: over 1.5 billion. Of 16.4 million IPv4 paths, 11.66 million (70.8%) are RPKI-valid, 4.79 million (29.1%) have no ROA, and 5,344 (0.03%) contradict one. The collector holds 1,129,444 IPv4 networks in 3.15 GB of memory.

Why it matters. This is the Internet's security score in one line. Two thirds of paths are now cryptographically checkable, and the invalid share is tiny because most large carriers drop invalid routes.

Command 2 of 11

IPv6 is better protected than IPv4

route-views> show bgp ipv6 unicast summary | include RPKI|network entries
Path RPKI states: 2314874 valid, 472953 not found, 1425 invalid
263194 network entries using 71588768 bytes of memory

What you see. The IPv6 table: 263,194 networks, 2.31 million valid paths (83.0%), 472,953 not found (17.0%), 1,425 invalid (0.05%).

Why it matters. IPv6 space was allocated after RPKI existed, and it is twelve points better protected than IPv4. If you run IPv6, publishing ROAs is the easiest win you have.

Command 6 of 11

A loose ROA: only two of four /24s announced, all four authorized

route-views> show ip bgp 1.6.0.0/22 longer-prefixes | include /2
V*   1.6.0.0/22       209.124.176.223                        0 101 11164 4637 64049 55836 9583 i
V*   1.6.1.0/24       209.124.176.223                        0 101 11164 4637 64049 55836 9583 i
V*   1.6.2.0/24       209.124.176.223                        0 101 11164 4637 64049 55836 9583 i

What you see. Three entries inside 1.6.0.0/22: the /22 and two /24s (1.6.1.0 and 1.6.2.0). The filter shows one line per prefix. 1.6.0.0/24 and 1.6.3.0/24 are not announced, yet the ROA (maxLength 24) authorizes all four.

Why it matters. Anyone forging AS 9583 as the origin could announce the two missing /24s, and they would be RPKI-valid and win on longest match. Fix: exact-length ROAs only (RFC 9319).

The RPKI caches behind origin validation

route-views> show ip bgp rpki servers | include neighbor is|Prefixes|attempts|failures
BGP SOVC neighbor is 128.223.157.83/3323 connected to port 3323
  Prefixes 1029922
  Connection attempts: 1920
  Connection failures: 1390
BGP SOVC neighbor is 128.223.157.89/3323 connected to port 3323
  Prefixes 1165839
  Connection attempts: 3046
  Connection failures: 2958

What you see. Two RPKI caches, both connected. They hold 1,029,922 and 1,165,839 entries, about 136,000 apart. Lifetime failure counts are 1,390 of 1,920 and 2,958 of 3,046 connection attempts.

Why it matters. Origin validation is only as good as its cache. Run at least two validators from different software, protect the RTR session, and alert when they disagree.

Command 10 of 11

The collector under load

route-views> show processes cpu | include CPU utilization
CPU utilization for five seconds: 42%/1%; one minute: 43%; five minutes: 36%

What you see. CPU at 42% over five seconds, 43% over one minute and 36% over five minutes. An hour earlier, during the telemetry run, the same command showed 85-100%.

Why it matters. Load swings with BGP churn and with the number of people querying the public login. Production routers keep monitoring off the control plane with BMP or streaming telemetry.
