The Header

Chapter 1: One Login, the Whole Internet · 3 November 2026 · Ioannis Alexander Konstas

Snapshot note. The session in this chapter was captured on 17 October 2021 at 17:33. The figures describe the Internet as it was then; the method is unchanged. For a current session (3 November 2026), and how the numbers have moved in five years, see Chapter 2, Part 8.

The first block of show ip bgp summary describes the router and its BGP table. Every line carries meaning.

LineValueWhat it tells you
BGP router identifier 128.223.51.103, local AS number 6447AS 6447Route Views' own autonomous system. A collector: it receives routes and announces none.
BGP table version is 11424091651.14 billionIncrements on every best-path change since the process started. This is the Internet's churn, and it never stops.
Path RPKI states: 6502331 valid, 13437858 not found, 17810 invalid32.6% / 67.3% / 0.09%Origin validation of every path (the three numbers add up exactly to the path count). A third of paths are cryptographically proven, two thirds have no ROA, and 17,810 contradict a published ROA: leaks, hijacks or mistakes, visible because a collector does not filter.
916896 network entries916,896Unique IPv4 prefixes: the size of the global IPv4 table from this vantage point.
19957999 path entries≈ 21.8 per prefixOne copy of each prefix per full-table peer.
3265932/154547 BGP path/bestpath attribute entries3.27 M / 155 kUnique attribute sets. Twenty million paths share only 3.3 million sets, about six paths each. That sharing is why a full table fits in memory.
3013798 BGP AS-PATH entries3.0 millionDistinct routes through the Internet's graph.
174831 BGP community entries174,831Distinct community sets: the policy tags networks attach to routes.
BGP using 3610266520 total bytes of memory3.61 GBPath entries 2.39 GB, attributes 0.81 GB. About 3.9 KB per prefix at 22 views: why full-table routers are sized the way they are.
