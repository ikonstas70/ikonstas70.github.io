Core Concepts & Why These Tools Matter
§1

Running Your Own Bitcoin Node

A Bitcoin full node independently validates every transaction and block against the consensus rules — it trusts no third party. Running your own node means you are not relying on someone else's node to tell you what the blockchain says. This matters for privacy (you don't leak your addresses to a third-party API), for security (you verify your own balance independently), and for network health (every node strengthens decentralization).

Why Monitor It?

A Bitcoin node is a long-running daemon. Without monitoring, silent failures go undetected: the node may fall behind the chain tip, peer connections may drop, mempool may fill, or malicious peers may attempt eclipse attacks. The tools in this reference turn passive node operation into active infrastructure management.

Bitcoin Halving — What and Why

Every 210,000 blocks (~4 years), the Bitcoin protocol cuts the block subsidy in half. This is coded in the consensus rules — not administered by anyone. The halving controls Bitcoin's total supply cap of 21 million BTC and its issuance schedule. Understanding which phase a block belongs to is fundamental to analyzing miner economics and network security budget over time.

What Is the Genesis Block?

Block height 0 — the first block ever mined by Satoshi Nakamoto on January 3, 2009. Its hash is hardcoded into every Bitcoin client. The coinbase transaction cannot be spent (a quirk of the original implementation). The block's timestamp and Merkle root are fixed constants used to validate chain continuity. Querying the genesis block via multiple RPC methods is the standard sanity check for a freshly configured node.

What Is a Peer Eclipse Attack?

An eclipse attack isolates a node by monopolizing all of its peer connections with attacker-controlled nodes. The victim node only sees the attacker's view of the chain. The security monitor watches for sudden inbound peer spikes, unusual peer subversion strings (/Satoshi:0.1.0/ style), and geographic peer concentration — all early eclipse indicators.

Live Block Monitor
§3

Polls bitcoin-core.cli getblockcount every 10 seconds. When a new block is detected, fetches full block data via getblock + getblockstats and renders it in a 100-column terminal box. Also appends every new block to bitcoin_block_log.txt for historical review.

Why it matters: Bitcoin produces a block roughly every 10 minutes. If your monitor stops showing new blocks, your node has either stalled (stuck at a chain tip), lost peers, or encountered a consensus failure. This is your first alert for node health issues.
bitcoin_block_monitor.py — complete script
import json, subprocess, time, os
from datetime import datetime, timezone

BOX_WIDTH     = 100
POLL_INTERVAL = 10   # seconds between height checks

def run_cli(*args):
    # Runs bitcoin-core.cli and returns stdout string, or None on error
    try:
        r = subprocess.run(["bitcoin-core.cli", *args],
                            stdout=subprocess.PIPE, stderr=subprocess.PIPE, check=True)
        return r.stdout.decode().strip()
    except subprocess.CalledProcessError as e:
        print(f"[!] CLI error: {e.stderr.decode().strip()}")
        return None

def get_current_block_height():
    raw = run_cli("getblockcount")
    return int(raw) if raw else None

def get_block_data(height):
    block_hash = run_cli("getblockhash", str(height))
    if not block_hash: return None
    block_json = run_cli("getblock", block_hash, "1")
    return json.loads(block_json) if block_json else None

def display_block(block):
    ts   = datetime.fromtimestamp(block['time'], tz=timezone.utc).strftime('%Y-%m-%d %H:%M:%S UTC')
    rows = [
        ("Height",       block['height']),
        ("Hash",         block['hash']),
        ("Time",         ts),
        ("Transactions", block['nTx']),
        ("Size (bytes)",  block['size']),
        ("Weight",       block['weight']),
        ("Difficulty",   f"{block['difficulty']:,.0f}"),
        ("Merkle Root",  block['merkleroot']),
        ("Nonce",        block['nonce']),
        ("Version",      block['versionHex']),
    ]
    border = "+" + "─" * (BOX_WIDTH - 2) + "+"
    print(border)
    print(f"│{'NEW BLOCK DETECTED'.center(BOX_WIDTH-2)}│")
    print(border)
    for label, value in rows:
        line = f"  {label:<15}{value}"
        print(f"│{str(line):<{BOX_WIDTH-2}}│")
    print(border)

def main():
    print("[*] Bitcoin Block Monitor — polling every 10 seconds")
    last_height = None
    while True:
        height = get_current_block_height()
        if height and height != last_height:
            block = get_block_data(height)
            if block:
                display_block(block)
                # Append to log
                with open("bitcoin_block_log.txt", "a") as f:
                    f.write(json.dumps({"height": height, "hash": block['hash'],
                                          "time": block['time'], "ntx": block['nTx']}) + "\n")
                last_height = height
        time.sleep(POLL_INTERVAL)

if __name__ == "__main__":
    main()
Genesis Block Query — 6 Methods
§4

The genesis block (height 0, hash 000000000019d6689c085ae165831e934ff763ae46a2a6c172b3f1b60a8ce26f) is the immutable anchor of the entire Bitcoin blockchain. Querying it via six different interfaces validates that the node's RPC, JSON-RPC, and REST APIs all work. The coinbase transaction of the genesis block is unspendable — this is a known quirk of Satoshi's original implementation.

Why 6 methods? Each method exercises a different code path: the CLI binary, the HTTP JSON-RPC endpoint, the REST API, header-only queries, verbose decode levels, and raw hex output. If any method fails while others succeed, the failure points to a specific subsystem — not the node sync itself.
bitcoin_genesis_block_query.sh — all 6 methods
#!/usr/bin/env bash
CLI="${BITCOIN_CLI:-/snap/bin/bitcoin-core.cli}"
RPC_USER="${BITCOIN_RPC_USER:-user}"
RPC_PASS="${BITCOIN_RPC_PASS:-pass}"
RPC_HOST="127.0.0.1"
RPC_PORT="8332"

# ── Method 1: By block height via CLI (recommended) ──────────────
GENESIS_HASH=$("$CLI" getblockhash 0)
"$CLI" getblock "$GENESIS_HASH" | jq '{hash, height, time, nTx, size, difficulty, merkleroot, nonce}'

# ── Method 2: Header only (lighter / faster) ──────────────────────
"$CLI" getblockheader "$GENESIS_HASH" | jq '{hash, height, time, difficulty, mediantime, chainwork}'

# ── Method 3: Raw block data (hex) ────────────────────────────────
"$CLI" getblock "$GENESIS_HASH" 0    # verbosity 0 = raw hex serialization

# ── Method 4: Full JSON decode (verbosity 2 — all tx data) ────────
"$CLI" getblock "$GENESIS_HASH" 2 | jq '.tx[0] | {txid, locktime, vout: .vout[0]}'

# ── Method 5: JSON-RPC over HTTP (curl) ───────────────────────────
curl -s --user "$RPC_USER:$RPC_PASS" \
  --data-binary '{"jsonrpc":"1.0","id":"genesis","method":"getblock","params":["'$GENESIS_HASH'",1]}' \
  -H 'content-type: text/plain;' \
  "http://$RPC_HOST:$RPC_PORT/" | jq '.result | {hash, height, time, nTx}'

# ── Method 6: REST API (no auth required — local only) ────────────
curl -s "http://127.0.0.1:8332/rest/block/$GENESIS_HASH.json" | jq '{hash, height, time, nTx}'

Halving Phases Explorer
§5

Iterates through the block heights at each halving boundary (209,999 → 210,000, 419,999 → 420,000, etc.) and queries the actual coinbase transaction value at each boundary. This lets you observe the protocol-enforced subsidy cut in the raw blockchain data — not from a third-party source.

Why it matters: The halving is a consensus rule, not a policy. Verifying it in your own node's data confirms that the block you are examining actually enforces the subsidy schedule — critical for auditing miner behavior at epoch boundaries.
bitcoin_halving_phases_explorer.sh
#!/bin/bash

# Boundary block heights — start and end of each halving epoch
BLOCK_HEIGHTS=(1 209999 210000 419999 420000 629999 630000 839999 840000 1049999)

RED='\033[0;31m'; GREEN='\033[0;32m'; WHITE='\033[1;37m'; NC='\033[0m'

for ((i=0; i<${#BLOCK_HEIGHTS[@]}-1; i+=2)); do
    PHASE_START=${BLOCK_HEIGHTS[$i]}
    PHASE_END=${BLOCK_HEIGHTS[$((i+1))]}
    echo -e "${RED}Phase $((i/2+1)): Blocks $PHASE_START — $PHASE_END${NC}"

    # ── Fetch start block ──────────────────────────────────────────
    START_HASH=$(bitcoin-core.cli getblockhash "$PHASE_START" 2>/dev/null)
    if [[ $? -eq 0 ]]; then
        START_DATA=$(bitcoin-core.cli getblock "$START_HASH" 2)
        # coinbase value = first output of first (coinbase) transaction
        VALUE=$(echo "$START_DATA" | jq -r '.tx[0].vout[0].value')
        TS=$(echo "$START_DATA"    | jq -r '.time')
        DATE=$(date -d @$TS '+%Y-%m-%d %H:%M:%S')
        echo -e "  Start — height $PHASE_START | coinbase: ${WHITE}${VALUE} BTC${NC} | $DATE"
    fi

    # ── Fetch end block ────────────────────────────────────────────
    END_HASH=$(bitcoin-core.cli getblockhash "$PHASE_END" 2>/dev/null)
    if [[ $? -eq 0 ]]; then
        END_DATA=$(bitcoin-core.cli getblock "$END_HASH" 2)
        VALUE=$(echo "$END_DATA" | jq -r '.tx[0].vout[0].value')
        TS=$(echo "$END_DATA"    | jq -r '.time')
        DATE=$(date -d @$TS '+%Y-%m-%d %H:%M:%S')
        echo -e "  End   — height $PHASE_END   | coinbase: ${WHITE}${VALUE} BTC${NC} | $DATE"
    fi
    sleep 1
done

# Phase 5 — post-4th-halving spot checks
echo -e "${RED}Phase 5: Spot checks 850000 – 880000${NC}"
for HEIGHT in 850000 860000 870000 880000; do
    HASH=$(bitcoin-core.cli getblockhash "$HEIGHT" 2>/dev/null) || { echo "  height $HEIGHT not yet mined"; continue; }
    DATA=$(bitcoin-core.cli getblock "$HASH" 2)
    VALUE=$(echo "$DATA" | jq -r '.tx[0].vout[0].value')
    TS=$(echo "$DATA"    | jq -r '.time')
    echo -e "  Height $HEIGHT | coinbase: ${WHITE}${VALUE} BTC${NC} | $(date -d @$TS '+%Y-%m-%d')"
    sleep 1
done
Node Security Monitor
§6

Intelligent dashboard that runs heuristic threat detection against the live node state. Collects data from five RPC calls — getnetworkinfo, getpeerinfo, getblockchaininfo, getmempoolinfo, getchaintips — and applies structured checks every 20 seconds. Alerts write to a log file and optionally to syslog.

do for BAD in "${BAD_SUBS[@]}"; do [[ "$SUB" == *"$BAD"* ]] && log_alert "SUSPICIOUS PEER SUBVER: $SUB" done done # ── Heuristic: Chain tip divergence ────────────────────────────── echo "$TIPS" | jq -r '.[] | "\(.status) \(.hash) height=\(.height)"' | grep -v "^active " | while read line; do log_alert "CHAIN TIP: $line"; done # ── Dashboard output (top peers by ping) ────────────────────────── echo "$PEER_INFO" | jq -r 'sort_by(.pingtime) | .[:10] | .[] | " \(.addr | .[0:40])<35 ping=\(.pingtime*1000|round)ms in=\(.bytesrecv) out=\(.bytessent)"'
Live Price Ticker — Framed Terminal Display
§7

Fetches live prices for BTC, ETH, LTC, and DOGE from the Coinbase public spot price API every 10 seconds. Renders inside a fixed-width terminal frame. Color-codes each price: green for up, red for down, yellow for unavailable. Press Q to quit cleanly.

Why Coinbase API? The https://api.coinbase.com/v2/prices/{CURRENCY}-USD/spot endpoint is public, no auth required, and returns a simple JSON object. No API key needed for spot price reads. The rate limit is generous for a 10-second polling interval.
crypto_ticker_framed_centered.py
import requests, time, shutil, os

CURRENCIES    = ['BTC', 'ETH', 'LTC', 'DOGE']
UPDATE_SECS   = 10
FRAME_WIDTH   = 44

def fetch_price(currency):
    try:
        r = requests.get(f"https://api.coinbase.com/v2/prices/{currency}-USD/spot", timeout=5)
        r.raise_for_status()
        return float(r.json()['data']['amount'])
    except: return None

def format_change(cur, prev):
    if cur is None: return "\033[33mUnavailable\033[0m"
    if prev is None: return f"{cur:.2f}"
    diff = cur - prev
    color = "\033[32m" if diff >= 0 else "\033[31m"
    sign  = "+" if diff > 0 else ""
    return f"{color}{cur:.2f} ({sign}{diff:.2f})\033[0m"

def display(prev_prices):
    print("\033[H", end="")       # cursor to top — no scroll
    bar = "═" * FRAME_WIDTH
    print(bar)
    print("  CRYPTO PRICES (USD)".center(FRAME_WIDTH))
    print(bar)
    for c in CURRENCIES:
        price = fetch_price(c)
        print(f"  {c:5} {format_change(price, prev_prices.get(c))}")
        if price: prev_prices[c] = price
    print(bar)
    print("  [Q] Quit".center(FRAME_WIDTH))

def main():
    prev = {}
    try:
        while True:
            display(prev)
            time.sleep(UPDATE_SECS)
    except KeyboardInterrupt:
        print("\nExiting.")

if __name__ == "__main__":
    main()

JSON Price API Output
§8

Minimal script — fetches prices for BTC, ETH, LTC, DOGE and outputs a JSON object to stdout. Designed to be piped into other tools or called from a parent script that needs machine-readable price data without parsing terminal display output.

crypto_price_json_output.py
import requests, json, sys

CURRENCIES  = ['BTC', 'ETH', 'LTC', 'DOGE']
API_TIMEOUT = 5

def fetch_price(currency):
    try:
        r = requests.get(f"https://api.coinbase.com/v2/prices/{currency}-USD/spot", timeout=API_TIMEOUT)
        r.raise_for_status()
        return float(r.json()['data']['amount'])
    except: return None

if __name__ == "__main__":
    prices = {c: fetch_price(c) for c in CURRENCIES}
    print(json.dumps(prices, indent=2))

Colored Price Display with Change Tracking
§9

Enhanced version of the price tracker — runs in a continuous loop with configurable update interval (default 10s), tracks previous price to display delta with color coding, and handles API errors gracefully by printing to stderr without crashing the loop. Press any key + Enter to quit.

crypto_prices_colored_display_v2.py
import requests, time, sys, os, select

CURRENCIES      = ['BTC', 'ETH', 'LTC', 'DOGE']
API_TIMEOUT     = 5
UPDATE_INTERVAL = 10

def fetch_price(currency):
    url = f"https://api.coinbase.com/v2/prices/{currency}-USD/spot"
    try:
        r = requests.get(url, timeout=API_TIMEOUT)
        r.raise_for_status()
        return float(r.json()['data']['amount'])
    except requests.exceptions.RequestException as e:
        print(f"Error fetching {currency}: {e}", file=sys.stderr)
        return None

def format_change(current, previous):
    if current is None: return "\033[33mUnavailable\033[0m"
    if previous is None: return f"{current:.2f}"
    diff = current - previous
    if   diff > 0: return f"\033[32m{current:.2f} (+{diff:.2f})\033[0m"
    elif diff < 0: return f"\033[31m{current:.2f} ({diff:.2f})\033[0m"
    else:          return f"{current:.2f} (=)"

def display(prev_prices):
    os.system('clear')
    print("═" * 44)
    print(f"  {'Currency':<8}  {'Price (USD)'}")
    print("─" * 44)
    for c in CURRENCIES:
        price = fetch_price(c)
        print(f"  {c:<8}  {format_change(price, prev_prices.get(c))}")
        if price: prev_prices[c] = price
    print("═" * 44)

def main():
    prev_prices = {}
    try:
        while True:
            display(prev_prices)
            # Non-blocking stdin check — quit if input arrives
            if sys.stdin in select.select([sys.stdin], [], [], UPDATE_INTERVAL)[0]:
                break
    except KeyboardInterrupt: pass
    print("\nExiting.")

if __name__ == "__main__":
    main()
