Floating Static Routes: Backup Path Selection in Cisco Networks

Articles · July 2026 · Ioannis Konstas

Redundancy is only useful if the router actually fails over when it should — and does nothing when it shouldn't. A floating static route is the simplest tool in Cisco IOS for exactly that: a backup path that sits silently in reserve, invisible to the routing table, until the primary route disappears. No second routing protocol, no tracking scripts in the basic case — just one number, the Administrative Distance, doing the work.

The one rule it rests on

When a router has more than one way to reach the same destination from different sources, it decides which to trust using Administrative Distance (AD) — a preference value where lower means more trusted. The route with the lowest AD is the one installed and used.

Route sourceAdministrative Distance
Connected0
Static1
EIGRP (internal)90
OSPF110
RIP120

Here's the catch that makes floating statics necessary. A normal static route has an AD of just 1 — lower than every dynamic protocol. So if you configure a plain backup static route, it doesn't wait for anything; it beats your OSPF or EIGRP path immediately and becomes the primary. That's the opposite of what you want from a backup. The fix is to deliberately raise the static route's AD above the primary's, so it "floats" above the preferred path and only drops into the table when that path is gone.

Example 1: OSPF primary, static backup

Say the real path is learned through OSPF, which carries an AD of 110:

O 10.10.10.0/24 [110/20] via 192.168.1.2

You want a static route over a second link as backup, but it must not override OSPF. Configure it with an AD of 111 — one higher than OSPF — by appending the distance to the ip route command:

ip route 10.10.10.0 255.255.255.0 192.168.2.2 111
!                                              ^^^  administrative distance

Now compare: OSPF's AD 110 is lower than the static's AD 111, so OSPF wins and is installed. The static route stays out of the table entirely — floating, inactive. The moment the OSPF route is withdrawn (the link or neighbor fails), OSPF's entry is removed, the AD-111 static becomes the best remaining route, and IOS installs it. Traffic keeps flowing over the backup with no manual intervention. When OSPF recovers, its lower AD reclaims the table and the static floats back out of the way.

Example 2: EIGRP primary, static backup

The same idea, tuned to whatever the primary's AD happens to be. EIGRP internal routes carry an AD of 90:

D 172.16.0.0/16 [90/30720] via 10.1.1.1

So the floating backup just needs to be one higher — AD 91:

ip route 172.16.0.0 255.255.0.0 10.2.2.2 91

EIGRP's 90 beats the static's 91, EIGRP is preferred, and the static activates only if the EIGRP route drops. The pattern is always the same: set the backup's AD just above the primary's. Whatever protocol carries your primary — 90 for internal EIGRP, 110 for OSPF, 120 for RIP — pick a static AD one higher and it becomes a clean standby.

One caveat worth knowing

A static route's health is only as good as its next hop's reachability. If the static points out a directly connected interface that goes down, IOS pulls the route as expected. But if it points to a next-hop IP that stays reachable through some other path while the intended link is actually broken, the floating route can install when it shouldn't — or fail to. For links where that matters, pair the floating static with an IP SLA object tracking a reachability test, so the route only installs when the backup path is genuinely usable. For a straightforward WAN or Internet backup, though, the plain floating static is often all you need.

Why reach for a floating static

  • Simple backup connectivity — one line of configuration, no extra protocol to run or secure.
  • No second routing protocol — ideal where the backup link shouldn't participate in your IGP.
  • Explicit control — you decide the exact failover path, not an algorithm.
  • Built for WAN and Internet backups — the classic use case: a primary MPLS or fiber link with a secondary broadband or LTE path in reserve.
A floating static route is redundancy expressed as a single number. Primary path gets the lower Administrative Distance; the backup gets one higher and waits in the wings. IOS keeps the backup out of the table until the primary fails, then installs it automatically — clean failover, no dynamic protocol required.

This is the same Administrative-Distance machinery covered in Cisco IOS Path Selection — here it's simply turned into a deliberate failover tool.
