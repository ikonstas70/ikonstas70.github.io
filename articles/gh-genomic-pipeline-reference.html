Installation Guide — macOS

Everything below runs on macOS Apple Silicon (M1/M2/M3/M4) or Intel Mac. The only prerequisite is Homebrew — macOS's standard package manager.

Step 1 — Install Homebrew (if not already installed)

# Paste this into Terminal — it installs Homebrew
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Verify installation
brew --version

Step 2 — Install Core Bioinformatics Tools

# samtools — reads, indexes, and queries genome FASTA and BAM files
brew install samtools

# bcftools — reads, queries, and filters VCF variant call files
brew install bcftools

# htslib — provides bgzip (block gzip) and tabix (indexed compression)
brew install htslib

# bwa — aligns short DNA reads to a reference genome
brew install bwa

# Java — required by snpEff (annotation engine)
brew install openjdk@17
echo 'export PATH="/opt/homebrew/opt/openjdk@17/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

# Verify Java is working
java -version

Step 3 — Install snpEff (Variant Annotator)

snpEff is not on Homebrew — install it manually. It is a Java program distributed as a ZIP file.

# Create a working directory
mkdir -p ~/na12878_pipeline && cd ~/na12878_pipeline

# Download snpEff

Step 5 — Install Python Visualization Tools

# Install pip packages for plotting
pip3 install matplotlib pandas numpy biopython

# Verify

Downloading the Human Genome — The Single 3-Billion-Line File

The human genome reference (GRCh38) is a single compressed FASTA file. It contains the complete DNA sequence of a "consensus" human being — all 23 chromosome pairs, roughly 3.1 billion base pairs, written out as A/T/C/G characters and wrapped at 80 characters per line.

Why 80 characters per line? A historical computing standard inherited from IBM punch cards (80 columns) and early 80-column terminal screens. When bioinformatics software was first written in the 1980s–90s, this limit ensured files displayed correctly on any machine. The convention stuck and became the universal FASTA standard. Your 38.6 million line file = ~3 billion bases ÷ 80 characters per line.

Option A — Download GRCh38 from NCBI (Authoritative Source)

mkdir -p ~/na12878_pipeline && cd ~/na12878_pipeline

# Full primary assembly — all chromosomes — ~900 MB compressed (~3 GB unzipped)
curl -O https://ftp.ncbi.nlm.nih.gov/genomes/all/GCA/000/001/405/GCA_000001405.15_GRCh38/GCA_000001405.15_GRCh38_assembly_structure/Primary_Assembly/assembled_chromosomes/FASTA/chroms/GRCh38_major_release_seqs_for_alignment_pipelines.fa.gz

# OR — faster mirror from Ensembl
curl -O https://ftp.ensembl.org/pub/release-110/fasta/homo_sapiens/dna/Homo_sapiens.GRCh38.dna.primary_assembly.fa.gz

# OR — UCSC hg38 (same genome, different chromosome naming: chr1 vs 1)
rsync -avzP rsync://hgdownload.soe.ucsc.edu/goldenPath/hg38/bigZips/hg38.fa.gz .
NCBI vs Ensembl vs UCSC naming: These are all GRCh38 but chromosomes are named differently. NCBI/UCSC use chr1, chr2…. Ensembl uses 1, 2…. This matters — bcftools and tabix will fail if your VCF uses one naming convention and your reference uses another.

Option B — Download NA12878 Real Variant Calls (GIAB Gold Standard)

cd ~/na12878_pipeline

# High-confidence variant VCF for NA12878 against GRCh38
curl -O https://ftp-trace.ncbi.nlm.nih.gov/giab/ftp/release/NA12878_HG001/NISTv3.3.2/GRCh38/HG001_GRCh38_GIAB_highconf_CG-IllFB-IllGATKHC-Ion-10X-SOLID_CHROM1-X_v.3.3.2_highconf_PGandRTGphasetransfer.vcf.gz

# Download the index file too (required for tabix random access)
curl -O https://ftp-trace.ncbi.nlm.nih.gov/giab/ftp/release/NA12878_HG001/NISTv3.3.2/GRCh38/HG001_GRCh38_GIAB_highconf_CG-IllFB-IllGATKHC-Ion-10X-SOLID_CHROM1-X_v.3.3.2_highconf_PGandRTGphasetransfer.vcf.gz.tbi

Index the Reference Genome for Fast Querying

Before you can query specific coordinates, the genome file must be indexed. This creates a lookup table so tools can jump directly to any position without reading the entire file.

# Step 1 — Block-gzip compress the reference (if not already bgzip'd)
bgzip -c Homo_sapiens.GRCh38.dna.primary_assembly.fa.gz > ref_grch38.fna.bgz

# Step 2 — Build the FASTA index (.fai file)
samtools faidx ref_grch38.fna.bgz

# This creates ref_grch38.fna.bgz.fai — a lookup table of chromosome positions

# Step 3 — Index the VCF for random access
tabix -p vcf na12878.vcf.gz

# Step 4 — Index VCF with bcftools (alternative, creates .csi index)
bcftools index na12878.vcf.gz
What indexing does: Without an index, querying chr17 position 43,000,000 means reading every single line from the start of the file until you reach that position. With an index, the tool opens the file directly at that byte offset — like a book's index vs reading from page 1.

Complete Query Reference — Every Command Explained

This section covers every tool used to query the 3-billion-line genome file. Each command is broken down: what it does, why you use it, and what output to expect.

1. Stream a Compressed File Without Extracting It

gzcat reads a .gz file and outputs its contents as a text stream — no decompression to disk. This is the foundation of every genomic query on macOS.

# Stream the entire genome into your terminal (DO NOT run alone — will print forever)
gzcat ref_grch38.fna.bgz

# Always pipe gzcat into another command that controls the output
gzcat ref_grch38.fna.bgz | head -n 5        # first 5 lines only
gzcat ref_grch38.fna.bgz | wc -l             # count total lines (slow — reads all 38M)
gzcat ref_grch38.fna.bgz | grep "^>"         # show only chromosome headers

2. Peek at the File Without Opening It

# Show first 10 lines
gzcat ref_grch38.fna.bgz | head -n 10

# Show last 10 lines (reads entire file — slow on 3 GB)
gzcat ref_grch38.fna.bgz | tail -n 10

# Show first 20 lines of a specific chromosome (chr22)
gzcat ref_grch38.fna.bgz | sed -n '/^>chr22/,/^>/p' | head -n 20

# Count how many chromosomes are in the file
gzcat ref_grch38.fna.bgz | grep -c "^>"

3. samtools faidx — Query Exact Coordinates (Fastest Method)

samtools faidx uses the index to jump directly to any genomic coordinate in milliseconds — no reading from the start. This is how you query specific genes or regions.

# Pull a single base at a specific position
samtools faidx ref_grch38.fna.bgz chr17:43094464-43094464

# Pull the entire BRCA1 gene region
samtools faidx ref_grch38.fna.bgz chr17:43044295-43125483

# Pull a region from chromosome 22
samtools faidx ref_grch38.fna.bgz chr22:1-50000

# Pull multiple regions at once
samtools faidx ref_grch38.fna.bgz chr17:43044295-43125483 chr22:1-100000

# List all chromosomes and their sizes (from the .fai index)
cut -f1,2 ref_grch38.fna.bgz.fai

# Output format: FASTA header + sequence
# >chr17:43044295-43125483
# ATCGATCGATCG...

4. bcftools — Query the Variant Database (VCF File)

The VCF file contains 4.2 million positions where NA12878's DNA differs from the reference. bcftools is the primary tool for querying it.

# ─── BASIC QUERIES ───────────────────────────────

# Show VCF header (metadata about the file)
bcftools view -h na12878.vcf.gz | less

# Show first 10 variant records
bcftools view na12878.vcf.gz | grep -v "^#" | head -10

# Count total number of variants
bcftools view na12878.vcf.gz | grep -vc "^#"

# ─── FILTER BY CHROMOSOME / REGION ──────────────

# All variants on chromosome 22
bcftools view -r chr22 na12878.vcf.gz | less

# Variants in a specific gene region (BRCA1)
bcftools view -r chr17:43044295-43125483 na12878.vcf.gz

# Save region to a new file
bcftools view -r chr17:43044295-43125483 na12878.vcf.gz -o brca1_variants.vcf

# Multiple regions at once
bcftools view -r chr17:43044295-43125483,chr22:1-5000000 na12878.vcf.gz

# ─── FILTER BY VARIANT TYPE ──────────────────────

# Show only SNPs (single nucleotide changes)
bcftools view -v snps na12878.vcf.gz | head -20

# Show only indels (insertions + deletions)
bcftools view -v indels na12878.vcf.gz | head -20

# Count SNPs
bcftools view -v snps na12878.vcf.gz | grep -vc "^#"

# Count indels
bcftools view -v indels na12878.vcf.gz | grep -vc "^#"

# ─── STATISTICS ──────────────────────────────────

# Full stats report (ts/tv ratio, indel sizes, quality distribution)
bcftools stats na12878.vcf.gz > na12878_stats.txt
less na12878_stats.txt

# Quick summary stats
bcftools stats na12878.vcf.gz | grep "^SN"

# ─── ADVANCED QUERIES ────────────────────────────

# Extract only the chromosome, position, ref, alt columns
bcftools query -f '%CHROM\t%POS\t%REF\t%ALT\n' na12878.vcf.gz | head -20

# Count insertions (ALT longer than REF)
bcftools view -v indels na12878.vcf.gz | awk '!/^#/ && length($5) > length($4)' | wc -l

# Count deletions (REF longer than ALT)
bcftools view -v indels na12878.vcf.gz | awk '!/^#/ && length($4) > length($5)' | wc -l

# Find the largest indels (most disruptive)
bcftools view -v indels na12878.vcf.gz | awk '!/^#/ {print length($4)-length($5), $0}' | sort -n | tail -10

# Check if a specific position has a variant
bcftools view -r chr17:43094464-43094464 na12878.vcf.gz

5. tabix — Indexed Random Access (Jump to Any Position Instantly)

tabix is like a GPS for a compressed genomic file. Once a file is indexed, it can seek directly to any chromosome:position without reading from the start.

# Build a tabix index on a VCF (creates .tbi file)
tabix -p vcf na12878.vcf.gz

# Query a region directly — millisecond access on a 450 MB file
tabix na12878.vcf.gz chr17:43044295-43125483

# Query chromosome 22 entirely
tabix na12878.vcf.gz chr22

# List all chromosomes in the file
tabix -l na12878.vcf.gz

# Build a tabix index on a FASTA file
tabix -p fasta genome.fasta.gz

6. grep — Pattern Search Inside Any Genomic File

# Find all chromosome headers in FASTA
gzcat ref_grch38.fna.bgz | grep "^>"

# Find a specific chromosome header
gzcat ref_grch38.fna.bgz | grep "^>chr22"

# Show chr22 header + the next 5 lines of sequence
gzcat ref_grch38.fna.bgz | grep "^>chr22" -A 5

# Count how many lines contain a specific motif (e.g. BRCA1 gene ID)
bcftools view na12878.vcf.gz | grep -c "BRCA1"

# Search VCF for a specific rs-ID (dbSNP variant identifier)
bcftools view na12878.vcf.gz | grep "rs28897672"

# Count lines NOT starting with # (count actual variants, skip header)
bcftools view na12878.vcf.gz | grep -vc "^#"

7. sed — Stream Filter by Range

sed is the tool that isolates one chromosome from the 38-million-line genome stream.

# Isolate chromosome 22 from start to the next chromosome header
gzcat ref_grch38.fna.bgz | sed -n '/^>chr22/,/^>chr[^2]/p' | head -20

# How it works:
#   -n          suppress default printing
#   /^>chr22/   start printing when this pattern is matched
#   ,/^>chr/    stop printing when ANY new chromosome header is matched
#   p           print the matching range

# Isolate lines between two patterns and save to file
gzcat ref_grch38.fna.bgz | sed -n '/^>chr22/,/^>chrX/p' > chr22_only.fasta

8. awk — Column Math on Genomic Data

awk treats each line as columns separated by tabs. VCF files have 8+ tab-separated columns — awk lets you calculate on them.

# VCF column structure:
# $1=CHROM  $2=POS  $3=ID  $4=REF  $5=ALT  $6=QUAL  $7=FILTER  $8=INFO

# Print chromosome and position of every variant
bcftools view na12878.vcf.gz | awk '!/^#/ {print $1, $2}'

# Calculate indel size (positive = deletion, negative = insertion)
bcftools view -v indels na12878.vcf.gz | awk '!/^#/ {print length($4)-length($5), $1, $2}'

# Show only variants with quality score above 50
bcftools view na12878.vcf.gz | awk '!/^#/ && $6 > 50'

# Count variants per chromosome
bcftools view na12878.vcf.gz | awk '!/^#/ {count[$1]++} END {for(c in count) print c, count[c]}' | sort -V

9. snpEff — Annotate What Variants Actually Do

# Annotate chr22 only (memory-safe, ~3 GB RAM)
bcftools view -r chr22 na12878.vcf.gz | \
  java -Xmx8g -jar snpEff/snpEff.jar GRCh38.109 - > chr22_annotated.vcf

# Annotate full genome (requires 16 GB free RAM)
java -Xmx16g -jar snpEff/snpEff.jar GRCh38.109 na12878.vcf.gz > na12878_annotated.vcf 2>snpeff.log

# Monitor progress while running
tail -f snpeff.log

# After annotation — compress and index the output
bgzip na12878_annotated.vcf
tabix -p vcf na12878_annotated.vcf.gz

# Query annotated file for missense variants only
bcftools view na12878_annotated.vcf.gz | grep "missense_variant"

# Query annotated file for BRCA1 gene
grep BRCA1 snpEff_genes.txt

# Open the HTML summary report in browser
open snpEff_summary.html

The Woman Behind the Genome: NA12878

Who Is NA12878?

NA12878 is the sample identifier assigned to a real woman known within the global genomics community as HG001. She is a Utah resident of Northern and Western European ancestry — a mother, grandmother, and one of the most important people in the history of modern genetics. She voluntarily donated a blood sample to science, knowing it would be sequenced and made publicly available for research around the world.

Her genome has been sequenced more times than any other human genome in history. It serves as the foundational quality control standard used by every major sequencing center, software developer, and bioinformatics researcher on Earth.

The CEPH Collection (1980s)

NA12878's story begins with the Centre d'Etude du Polymorphisme Humain (CEPH), a French genetics institute founded in Paris in 1983. CEPH recruited large three-generation families and collected DNA samples from grandparents, parents, and children. These families, called the CEPH pedigrees, gave scientists the ability to track how genetic variants are inherited across generations — a process called linkage analysis.

NA12878 belongs to CEPH family 1463. The "NA" prefix stands for North American. The "12878" is her permanent, anonymized lab identifier. She is one member of a multi-generation family that donated samples together, allowing scientists to verify which variants she inherited from which parent.

Why this matters: Because three generations of her family donated DNA, researchers can phase NA12878's genome — meaning they can determine which variants came from her mother and which from her father. This is extremely rare and valuable. Most sequencing data cannot do this.

Genome in a Bottle (GIAB) — The Gold Standard

In 2011, the National Institute of Standards and Technology (NIST) launched the Genome in a Bottle Consortium. Their mission: create a human genome reference so deeply verified that it could be trusted as a universal benchmark. NA12878 was selected as the first subject.

Her genome was sequenced using every major sequencing technology available — Illumina short reads, Pacific Biosciences long reads, Oxford Nanopore, Complete Genomics, Ion Torrent, and more — and the results were cross-validated against each other to produce a high-confidence variant call set: a list of every position in her genome where she differs from the reference, with the highest confidence rating in the field.

What "300× coverage" means: Every single base in her 3-billion-base genome was read approximately 300 times independently. Normal clinical sequencing is 30×. NA12878 is 10× more deeply verified than clinical standard.

Her Scientific Legacy

NA12878's genome has been downloaded millions of times. It is used to:

  • Validate every new DNA sequencing machine before it goes to market
  • Test and benchmark bioinformatics software (aligners, variant callers, annotation tools)
  • Train machine learning models that detect cancer mutations and rare diseases
  • Calibrate clinical laboratory pipelines before they process real patient samples
  • Serve as a teaching resource — exactly as in this project

Every time a hospital sequences a cancer patient's tumor to find the right treatment, the pipeline that produced that result was likely validated against NA12878 first. Her contribution is immeasurable.

NIST Standard Reference Material SRM 8398: NA12878's DNA is sold as a certified laboratory standard. You can purchase a tube of her DNA from NIST. The proceeds support continued genomic research.

Core Data Pipeline: Stream, Filter, Truncate

The fundamental technique in this project is Unix piping — connecting tools so data flows through them sequentially in memory, never touching the disk. This allows processing a multi-gigabyte compressed genome file without ever extracting it.

Phase 1 — Stream
gzcat genome.fasta.gz
Decompresses on the fly, streams raw text into memory — no disk write
➔
Phase 2 — Filter
sed -n '/_chr22_/,/_chrX_/p'
Activates at chr22 header, stops at chrX — isolates one chromosome
➔
Phase 3 — Brakes
head -n 20
Captures 20 lines, sends upstream kill signal — prevents terminal flood
# Full command — isolate chr22 from a compressed 38M-line genome
gzcat genome_23chromosomes.fasta.gz | sed -n '/_chr22_/,/_chrX_/p' | head -n 20
PhaseCommandFunctionTechnical Advantage
1. Stream gzcat file.fasta.gz Reads and decompresses on the fly No disk extraction — saves multi-GB of storage and eliminates I/O bottleneck
2. Filter sed -n '/_chr22_/,/_chrX_/p' Suppresses all output until chr22 header is matched; stops at chrX Isolates one chromosome boundary instantly from millions of lines
3. Halt head -n 20 Captures first 20 lines, sends SIGPIPE upstream to terminate the pipeline Acts as system brakes — prevents flooding from 50M+ base pairs of sequence

Building the Personal Genome — NA12878 Consensus

A "personal genome" is constructed by taking the universal human reference sequence (GRCh38) and applying one individual's specific variant calls on top of it. The result is a FASTA file where every position reflects that person's actual DNA, not the generic average.

The Three Build Components

FileDescriptionStatus
na12878.vcf.gz Real variant calls from the GIAB consortium — 4.2M+ positions where NA12878 differs from reference Verified
na12878_consensus.fa 3 GB FASTA — GRCh38 reference with all GIAB variants applied. Chromosome lengths are shorter than reference at correct positions, confirming real indels were incorporated. Verified
ref_grch38.fna.bgz GRCh38 reference genome (bgzip compressed, samtools indexed) Indexed
Verification method: Chromosome lengths in the consensus FASTA are shorter than GRCh38 at specific locations. This is the expected signature when real deletions (indels) are applied — it confirms the pipeline worked correctly and this is genuine NA12878 sequence, not a copy of the reference.

Algorithmic Gap Resolution

An Unassigned segment does not mean missing DNA. It means those nucleotides match multiple reference panels with equal statistical confidence — the algorithm cannot choose a winner. By examining what flanks the gap on both sides (the flanking context resolution method), the underlying structure becomes clear.

Gaps A & B — Chromosome 3, Copy 1

A: 93.9M–96.5M (2.60 Mb)  |  B: 137.0M–138.9M (1.88 Mb)

Both gaps are embedded inside a dominant long-range Greek & Balkan / Southern European ancestral block. They are small, both flanks carry identical signatures — these are uniform European blocks with common polymorphic variations that the reference panel cannot sub-classify. No lineage break. Continuous Aegean heritage.

Gap C — Chromosome 4, Copy 2

C: 155.3M–156.6M (1.32 Mb)

This is a textbook meiotic recombination breakpoint. The DNA upstream of 155,273,743 tracks to the Southern European / Italian reference panel. The DNA immediately downstream of 156,602,205 transitions directly into a West Asian & North African / Cypriot segment. The gap is the precise structural bridge linking the European and Eastern Mediterranean ancestral branches.

Gaps D & E — Chromosome 13

D: 49.5M–51.2M (1.72 Mb)  |  E: 105.2M–106.2M (1.04 Mb)

Gap D is an internal Southern European transition. Gap E is tightly flanked by a general Southern European segment and a Greek & Balkan block, confirming continuous Greek heritage across both boundaries.

Gaps F, G, H — Chr 18, 19, 21

F: 51.7M–53.8M  |  G: 14.7M–15.9M  |  H: 21.8M–24.7M

These are consistently bounded on one side by Anatolian / West Asian blocks and on the other by Southern European / Greek segments. They act as regional transition boundaries — reflecting centuries of historic genetic overlap between the populations of Asia Minor, Cyprus, and the Aegean basin.

Mitochondrial Haplogroup: H15a1

Mitochondrial DNA (mtDNA) is inherited exclusively through the maternal line — mother to child, unchanged except for rare mutations. Every mutation that accumulates in the mtDNA over thousands of generations creates a branch in the maternal family tree. The terminal branch is the haplogroup.

[Macro-Haplogroup H] — ~20,000 BCE — Europe / Near East (post-Last Glacial Maximum expansion) │ └──► [Sub-Clade H15] ~5,150 BCE — Neolithic branching in the Near East / Aegean corridor │ └──► [H15a] — Sub-branch defined by position 16298 transition │ └──► [H15a1] ~3,000 BCE — Bronze Age terminal mutation Defining: pos 1023, 1438, 16298, 8152

The Four Defining Mutations

PositionRole
1023 & 1438Branch separation within the ancient H15 lineage — splits H15 from other H sub-groups
16298Establishes the H15a sub-branch — the hypervariable region transition
8152The definitive mutation locking lineage directly into H15a1 — the terminal identifier

Modern Geographic Distribution

Unlike broad Western European H branches that dominate the Iberian Peninsula and Atlantic coast, modern H15a1 carriers concentrate specifically around:

  • Greece & the Aegean Islands
  • Cyprus
  • Armenia
  • Iran & northern Iraq
  • Tajikistan & the Caucasus corridor

This distribution maps directly onto the autosomal chromosome pattern in Section 5 — the same Eastern Mediterranean / Anatolia / Levant signature appears in both independent data streams.

Why H15a1 matters scientifically: Because mtDNA is non-recombining (it does not shuffle like autosomal DNA), the haplogroup is a pure maternal signal going back 5,000+ years. It tells us about the population your maternal ancestors lived in — their migration routes, climate adaptations, and historical movements — independent of any paternal influence.

How the Comparison Pipeline Works

When comparing this profile's chromosome segments to the central database, the process follows these steps:

  1. Phased segment extraction: 23andMe's internal algorithm phases the ~650,000 SNP positions into maternal and paternal haplotypes (Copy 1 / Copy 2)
  2. Reference panel matching: Each phased segment is compared against 31 reference populations using a Hidden Markov Model (HMM) — the same statistical method used in scientific population genetics
  3. Boundary detection: Recombination breakpoints are identified where population signatures change — these are the segment boundaries in the coordinate ledger
  4. Confidence thresholding: At 0.5 threshold, segments are only assigned when the top reference panel match has at least 50% posterior probability — tighter than the default 0.3 setting
  5. Gap classification: Regions where no panel exceeds the threshold are marked Unassigned — these are the 8 gap windows in the dataset
