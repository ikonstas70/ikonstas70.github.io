Network Automation with Netmiko

Articles · July 2026 · Ioannis Konstas

Not every device speaks a clean API. Vast fleets of switches and routers still expose only the CLI over SSH, and the pragmatic bridge to automating them is Netmiko — a Python library that wraps SSH, handles the vendor-specific quirks (prompts, paging, enable mode), and lets you script against network gear as if it were a well-behaved tool. It's the workhorse for teams migrating from "log in and type" toward real infrastructure-as-code.

Why not just script SSH yourself?

Because raw SSH to a network device is a swamp of edge cases: the --More-- pager, per-vendor prompts, enable/config mode transitions, banners, and timing. Netmiko encapsulates all of it behind a consistent interface across dozens of platforms (Cisco IOS/NX-OS, Arista, Juniper, and more), so your logic stays clean.

Read state safely

Start with read-only operations — they can't break anything and immediately prove value. Netmiko can even parse output into structured data via TextFSM/Genie, turning screen-scraping into real objects:

from netmiko import ConnectHandler

device = {
    "device_type": "cisco_ios",
    "host": "10.0.0.1",
    "username": "admin",
    "password": get_secret("r1"),     # never hard-code; pull from a vault/env
    "fast_cli": True,
}

with ConnectHandler(**device) as conn:      # context manager -> always disconnects
    # use_textfsm parses the table into a list of dicts, not a blob of text
    interfaces = conn.send_command("show ip interface brief", use_textfsm=True)

for intf in interfaces:
    if intf["status"] != "up":
        print(f"DOWN: {intf['interface']} ({intf['ip_address']})")

Push config — with a safety net

Configuration changes are where automation earns trust or loses it. Three disciplines make it safe: send config as a list (Netmiko enters config mode for you), save explicitly only after verifying, and — critically — never lock yourself out.

commands = [
    "interface Loopback100",
    "description managed-by-automation",
    "ip address 10.100.0.1 255.255.255.255",
]

with ConnectHandler(**device) as conn:
    output = conn.send_config_set(commands)     # enters/exits config mode
    # Verify the change did what you expected BEFORE persisting it
    check = conn.send_command("show ip interface brief | include Loopback100")
    if "10.100.0.1" in check:
        conn.save_config()                       # write mem / copy run start
    else:
        raise RuntimeError(f"change did not apply cleanly: {output}")

Scale to a fleet — concurrently

One device at a time is a demo; the point is a hundred at once. Run them in parallel with a thread pool (network I/O is the bottleneck, so threads are ideal), and — the rule that separates professionals from outages — collect results, don't let one failure abort the batch:

from concurrent.futures import ThreadPoolExecutor, as_completed

def audit(host: str) -> tuple[str, str]:
    dev = {**base, "host": host}
    try:
        with ConnectHandler(**dev) as c:
            return host, c.send_command("show version | include uptime")
    except Exception as e:                        # unreachable, auth fail, timeout
        return host, f"ERROR: {e}"

results = {}
with ThreadPoolExecutor(max_workers=20) as pool:
    futures = {pool.submit(audit, h): h for h in inventory}
    for f in as_completed(futures):
        host, out = f.result()
        results[host] = out                       # one bad device can't stop the rest

Where Netmiko fits in the bigger picture

Netmiko is the low-level SSH engine. Above it sit richer frameworks — NAPALM for vendor-neutral getters and config replace/rollback, and Nornir for a pure-Python automation framework with inventory and concurrency built in (it often uses Netmiko underneath). For declarative fleet management, Ansible's network modules cover much of the same ground. The progression is natural: script tasks with Netmiko, graduate to Nornir/NAPALM as your inventory and safety needs grow.

Operating rules

  • Credentials from a vault or environment, never in code or version control.
  • Read before you write — build and trust your read-only automation first.
  • Verify then save — confirm the change applied before persisting; keep a rollback.
  • Idempotence and dry-runs — running twice should be safe; preview diffs where the tooling allows.
  • Log everything — an audit trail of what changed, where, and by whom.
Netmiko turns the CLI into an API you can trust — if you read before you write, verify before you save, and let a fleet fail one device at a time. It's the honest bridge from "log in and type" to infrastructure-as-code.
