Public-Key Cryptosystems Based on the Discrete Logarithm Problem

Articles · 2026 · Ioannis Konstas

Public-key cryptography depends on trapdoor one-way functions: mathematical operations that are computationally efficient in the forward direction but intractable to reverse without specific private trapdoor knowledge. Alongside integer factorization (the basis of RSA), the Discrete Logarithm Problem (DLP) constitutes the primary mathematical foundation for secure key exchange, asymmetric encryption, and digital signature algorithms across the global internet infrastructure.

1. The Discrete Logarithm Problem (DLP)

Let G be a finite cyclic group of order n generated by an element g ∈ G. For any element y ∈ G, the discrete logarithm of y with respect to base g is the unique integer x ∈ ℤn such that:

gˣ = y   (in group G)

In the multiplicative group of integers modulo a prime p, denoted ℤp* = {1, 2, ..., p − 1}:

y ≡ gˣ (mod p)

The Asymmetry

  • Forward Direction (Modular Exponentiation): Given base g, exponent x, and modulus p, computing y ≡ gˣ (mod p) requires only O(log x · log² p) operations via repeated squaring (square-and-multiply algorithm). Even for 4096-bit parameters, this completes in sub-milliseconds on modern hardware.
  • Inverse Direction (Discrete Logarithm): Given base g, result y, and modulus p, finding x = log_g(y) is computationally infeasible for appropriately sized groups without knowledge of the private exponent.

Why DLP Is Fundamental to Asymmetric Cryptography

Property Cryptographic Significance
Group Agility DLP is not restricted to integers modulo p; it transfers to points on elliptic curves E(𝔽p), yielding equivalent cryptographic strength with substantially smaller keys (e.g., 256-bit ECC vs. 3072-bit RSA/DH).
Independent Hardness Assumption Provides a distinct mathematical framework independent of integer factorization. A theoretical breakthrough against composite factoring does not automatically break DLP over prime groups or elliptic curves.
Enabling Advanced Primitives Forms the foundation for zero-knowledge proofs (Schnorr protocols), verifiable secret sharing (Pedersen commitments), multi-party computation (MPC), and blind signatures.

2. Diffie-Hellman Key Exchange (DHKE)

Introduced in 1976 by Whitfield Diffie and Martin Hellman, DHKE was the first published mechanism enabling two parties to establish a shared cryptographic secret over an unencrypted, monitored channel without ever transmitting the secret itself.

       Alice (Private: a)                                  Bob (Private: b)
  ─────────────────────────────                       ───────────────────────────
   Public Parameters: (p, g)                           Public Parameters: (p, g)
   
   Computes: A = gᵃ mod p          ─── Public A ───►   Computes: B = gᵇ mod p
                                   ◄─── Public B ───
   
   Computes Shared Secret:                             Computes Shared Secret:
   K = Bᵃ mod p                                        K = Aᵇ mod p
     = (gᵇ)ᵃ = gᵃᵇ mod p                                 = (gᵃ)ᵇ = gᵃᵇ mod p

Protocol Execution

  1. Parameter Selection: Both parties agree on a large prime p and a generator g ∈ ℤp*.
  2. Key Generation:
    • Alice picks private exponent a ∈ [2, p − 2] and sends public key A = gᵃ mod p.
    • Bob picks private exponent b ∈ [2, p − 2] and sends public key B = gᵇ mod p.
  3. Shared Secret Derivation:
    • Alice computes: K = Bᵃ mod p = (gᵇ)ᵃ = gᵃᵇ mod p.
    • Bob computes: K = Aᵇ mod p = (gᵃ)ᵇ = gᵃᵇ mod p.
    • Both parties now share K = gab mod p. An adversary observing (p, g, A, B) must solve the Computational Diffie-Hellman problem to extract K.

Worked Example

Using parameters: p = 23, g = 5:

Step Alice Bob Network / Eavesdropper
1. Private Key a = 6 b = 15 Secret
2. Public Key A = 5⁶ mod 23 = 8 B = 5¹⁵ mod 23 = 19 Exchanges A = 8, B = 19
3. Shared Secret K = 19⁶ mod 23 = 2 K = 8¹⁵ mod 23 = 2 Derives K = 2

Why Diffie-Hellman Is Critical

  • Eliminated the Key Distribution Problem: Removed the operational necessity of pre-shared symmetric keys or trusted physical couriers.
  • Perfect Forward Secrecy (PFS): In Ephemeral Diffie-Hellman (DHE / ECDHE), key pairs are generated on the fly per session and wiped immediately. Even if the server's long-term private identity key is compromised later, recorded historical network traffic cannot be decrypted.
  • Universal Deployment: Directly secures the cryptographic handshakes of TLS 1.3, SSH-2, IPsec (IKEv2), WireGuard, and the Signal Protocol.

3. ElGamal Public-Key Encryption

Published in 1985 by Taher Elgamal, this system adapted the Diffie-Hellman key agreement mechanism into a full asymmetric encryption and digital signature scheme. Rather than encrypting directly through exponentiation of the message (as in RSA), ElGamal uses the recipient's public key to create an ephemeral Diffie-Hellman shared value that masks the plaintext.

                                  ElGamal Encryption
  
   Public Key: (p, g, y = gˣ mod p)                    Private Key: x
  
   Sender (Alice):                                     Receiver (Bob):
   - Choose ephemeral random k                         - Receives (c₁, c₂)
   - Compute c₁ = gᵏ mod p                             - Computes shared mask: s = c₁ˣ mod p
   - Compute shared mask s = yᵏ mod p                  - Computes s⁻¹ mod p via EEA
   - Compute c₂ = m · s mod p                          - Recovers message: m = c₂ · s⁻¹ mod p
   
   Ciphertext: C = (c₁, c₂)

Mathematical Specification

  1. Key Generation (Bob):
    • Selects prime p and generator g.
    • Selects private key x ∈ [2, p − 2].
    • Computes public key y = gˣ mod p. Public key: (p, g, y).
  2. Encryption (Alice):
    • Plaintext message m ∈ ℤp*.
    • Selects a fresh random ephemeral nonce k ∈ [2, p − 2] with gcd(k, p − 1) = 1.
    • Computes ciphertext pair (c₁, c₂): 
      c₁ = gᵏ mod p
c₂ = (m · yᵏ) mod p
  3. Decryption (Bob):
    • Computes shared mask factor: s = c₁ˣ mod p = (gᵏ)ˣ = gᵏˣ mod p.
    • Computes the modular inverse s⁻¹ mod p via the Extended Euclidean Algorithm.
    • Recovers original message: 
      m = (c₂ · s⁻¹) mod p = (m · yᵏ · (gᵏˣ)⁻¹) mod p = m mod p

Numerical Worked Example

Parameters: p = 23, g = 5, Bob's private key x = 6.

  • Bob's Public Key: y = 5⁶ mod 23 = 8. Bob publishes (p=23, g=5, y=8).
  • Alice Encrypts Message m = 7:
    • Alice picks ephemeral nonce k = 15.
    • c₁ = 5¹⁵ mod 23 = 19.
    • s = yᵏ mod p = 8¹⁵ mod 23 = 2.
    • c₂ = (7 · 2) mod 23 = 14.
    • Alice transmits ciphertext: (c₁, c₂) = (19, 14).
  • Bob Decrypts:
    • Bob calculates mask: s = 19⁶ mod 23 = 2.
    • Computes inverse: 2⁻¹ mod 23 = 12 (since 2 × 12 = 24 ≡ 1 mod 23).
    • Reconstructs plaintext: m = (14 · 12) mod 23 = 168 mod 23 = 7. ✓

Distinct Capabilities & Importance

Capability Mechanism Cryptographic Benefit
Semantic Security (IND-CPA) Probabilistic encryption: each encryption uses a fresh random ephemeral nonce k. Encrypting the same message twice produces completely different ciphertexts, preventing pattern leakage and chosen-plaintext dictionary attacks.
Multiplicative Homomorphism Multiplying two ciphertexts component-wise yields an encryption of the product of plaintexts: (c₁,₁c₂,₁,   c₁,₂c₂,₂) decrypts to m₁ · m₂ mod p. Fundamental building block for privacy-preserving computation, electronic voting tallying systems, and cryptographic mixnets.
Origin of Modern Digital Signatures ElGamal Signature Scheme binds message hashes via ephemeral exponents. Directly inspired the Digital Signature Algorithm (DSA) standardized in NIST FIPS 186, which evolved into ECDSA and Schnorr (BIP-340).

4. Cryptanalysis & Hardness Comparison

The security of DLP-based cryptosystems depends on the group in which operations take place:

Group Family Best Known Classical Attack Computational Complexity NIST 128-Bit Key Recommendation
Finite Field ℤp* (FFDHE / DSA) Index Calculus & Number Field Sieve (NFS) Subexponential: L_p[1/3, c] = exp((c + o(1))(ln p)¹/³ (ln ln p)²/³) p ≥ 3072 bits (Subgroup q ≥ 256 bits)
Elliptic Curves E(𝔽p) (ECDH / ECDSA) Pollard's ρ / Baby-Step Giant-Step Exponential (Generic): O(√n) ≈ 2^{b/2} 256-bit curve (Curve25519, secp256r1)

Engineering Hardening Guidelines

  • Safe Primes (Sophie Germain): For finite-field DH (RFC 3526 / RFC 7919 MODP groups), select primes where p = 2q + 1 with q prime. This eliminates small sub-order groups vulnerable to the Pohlig-Hellman algorithm.
  • Subgroup Confinement Validation: Always validate that incoming public keys satisfy 1 < A < p − 1 and A^q ≡ 1 (mod p) before deriving secrets to protect against small-subgroup attacks.
  • Constant-Time Arithmetic: Exponentiation (e.g., Montgomery Ladder) must run in constant time regardless of key bits to prevent side-channel timing leaks (SPA/DPA).
  • Post-Quantum Horizon: Shor's algorithm solves both DLP and integer factorization in polynomial time O((log p)³) on quantum hardware. Production deployments are transitioning to NIST post-quantum standards (ML-KEM-768 / ML-DSA).
