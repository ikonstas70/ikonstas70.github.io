Public-Key Cryptosystems Based on the Discrete Logarithm Problem

Articles · 2026 · Ioannis Konstas

Public-key cryptography depends fundamentally on trapdoor one-way functions: operations that are computationally trivial to compute in the forward direction but intractable to reverse without secret knowledge. Alongside integer factorization (RSA), the Discrete Logarithm Problem (DLP) forms the primary mathematical pillar for secure key exchange, asymmetric encryption, and digital signatures across modern internet infrastructure.

1. The Discrete Logarithm Problem (DLP)

Mathematical Formulation

Let G be a finite cyclic group of order n generated by an element g ∈ G. For any target element y ∈ G, the discrete logarithm of y to the base g is the unique integer x ∈ ℤn satisfying:

gˣ = y   (in group G)

In the multiplicative group of integers modulo a large prime p (denoted ℤp* = {1, 2, ..., p − 1}):

y ≡ gˣ (mod p)

The computational asymmetry that makes this a one-way function:

  • Forward Direction (Modular Exponentiation): Given g, x, and p, computing y ≡ gˣ (mod p) requires only O(log x · log² p) operations via repeated squaring (square-and-multiply). Even for 4096-bit numbers, this completes in sub-milliseconds on modern CPUs.
  • Reverse Direction (Discrete Logarithm): Given g, y, and p, finding the exponent x = log_g(y) is computationally infeasible for sufficiently large primes, requiring astronomical compute resources.

Why DLP is Critical

PropertyCryptographic Impact
Clean Group AbstractionDLP is not limited to integers modulo p; it extends naturally to elliptic curves E(𝔽p), allowing compact key sizes with exponential security scaling.
Independent Security AssumptionProvides a vital cryptographic alternative to integer factorization (RSA). Even if single-modulus factoring sees breakthroughs, DLP parameter groups remain distinct.
Foundation for Advanced PrimitivesPowers zero-knowledge proofs (Schnorr Identification), verifiable secret sharing (Pedersen commitments), threshold cryptography, and anonymous credentials.

2. Diffie-Hellman Key Exchange (DHKE)

Published in 1976 by Whitfield Diffie and Martin Hellman, DHKE was the breakthrough protocol that solved the fundamental key distribution problem: enabling two untrusted endpoints to negotiate a shared secret over an insecure channel without transmitting the secret itself.

       Alice (Private: a)                                  Bob (Private: b)
  ─────────────────────────────                       ───────────────────────────
   Public Parameters: (p, g)                           Public Parameters: (p, g)
   
   Computes: A = gᵃ mod p          ─── Public A ───►   Computes: B = gᵇ mod p
                                   ◄─── Public B ───
   
   Computes Shared Secret:                             Computes Shared Secret:
   K = Bᵃ mod p                                        K = Aᵇ mod p
     = (gᵇ)ᵃ = gᵃᵇ mod p                                 = (gᵃ)ᵇ = gᵃᵇ mod p

Step-by-Step Protocol Flow

  1. Domain Setup: A large prime p and a base generator g ∈ ℤp* are agreed upon publicly.
  2. Key Generation:
    • Alice chooses private key a ∈ [2, p − 2] and sends public key A = gᵃ mod p.
    • Bob chooses private key b ∈ [2, p − 2] and sends public key B = gᵇ mod p.
  3. Secret Agreement:
    • Alice calculates: K_A = Bᵃ mod p = (gᵇ)ᵃ = gᵃᵇ mod p
    • Bob calculates: K_B = Aᵇ mod p = (gᵃ)ᵇ = gᵃᵇ mod p
    • Both arrive at the identical shared value K = gab mod p. An eavesdropper observing (p, g, A, B) cannot compute K without solving the Computational Diffie-Hellman problem.

Concrete Worked Example

Let public parameters be p = 23 and generator g = 5.

StepAliceBobEavesdropper (Eve) Sees
1. Private Key Selectiona = 6 (kept secret)b = 15 (kept secret)Nothing
2. Public Key ComputationA = 5⁶ mod 23 = 15625 mod 23 = 8B = 5¹⁵ mod 23 = 19A = 8, B = 19
3. Secret DerivationK = 19⁶ mod 23 = 47045881 mod 23 = 2K = 8¹⁵ mod 23 = 2Must solve 5ˣ ≡ 8 (mod 23)

Both Alice and Bob derived K = 2 independently.

Why Diffie-Hellman Is Indispensable

  • Perfect Forward Secrecy (PFS): In ephemeral modes (DHE / ECDHE), temporary key pairs (a, b) are generated dynamically per session and purged from memory immediately following derivation. If a long-term server certificate is compromised in the future, past recorded sessions cannot be decrypted.
  • The Backbone of Transport Security: Directly establishes session keys in TLS 1.3, SSH-2, IPsec (IKEv2), WireGuard, and the Signal Protocol.

3. ElGamal Public-Key Encryption

Developed in 1985 by Taher Elgamal, this system extended Diffie-Hellman into a complete public-key encryption and digital signature suite. While RSA performs encryption via modular exponentiation directly on the message, ElGamal uses the public key to establish a Diffie-Hellman shared mask that blindingly encapsulates the plaintext.

                                  ElGamal Encryption
  
   Public Key: (p, g, y = gˣ mod p)                    Private Key: x
  
   Sender (Alice):                                     Receiver (Bob):
   - Choose ephemeral random k                         - Receives (c₁, c₂)
   - Compute c₁ = gᵏ mod p                             - Computes shared mask: s = c₁ˣ mod p
   - Compute shared mask s = yᵏ mod p                  - Computes s⁻¹ mod p via EEA
   - Compute c₂ = m · s mod p                          - Recovers message: m = c₂ · s⁻¹ mod p
   
   Ciphertext: C = (c₁, c₂)

Protocol Mechanics

  1. Key Generation (Bob):
    • Selects prime p and generator g.
    • Selects private key x ∈ [2, p − 2].
    • Publishes public key y = gˣ mod p. Bob's full public key is (p, g, y).
  2. Encryption (Alice):
    • Plaintext message m ∈ ℤp*.
    • Selects random ephemeral nonce k ∈ [2, p − 2] where gcd(k, p − 1) = 1.
    • Computes ciphertext pair (c₁, c₂): 
      c₁ = gᵏ mod p
c₂ = (m · yᵏ) mod p
  3. Decryption (Bob):
    • Computes shared mask: s = c₁ˣ mod p = (gᵏ)ˣ = gᵏˣ mod p.
    • Computes modular inverse s⁻¹ mod p using the Extended Euclidean Algorithm.
    • Recovers original message: 
      m = (c₂ · s⁻¹) mod p = (m · yᵏ · (gᵏˣ)⁻¹) mod p = m mod p

Worked Numerical Example

Using parameters: p = 23, g = 5, Bob's private key x = 6.

  • Bob's Public Key: y = 5⁶ mod 23 = 8. Public key: (23, 5, 8).
  • Alice Encrypts Message m = 7:
    • Alice chooses ephemeral nonce k = 15.
    • c₁ = 5¹⁵ mod 23 = 19.
    • s = yᵏ mod p = 8¹⁵ mod 23 = 2.
    • c₂ = (m · s) mod 23 = (7 · 2) mod 23 = 14.
    • Ciphertext sent: (c₁, c₂) = (19, 14).
  • Bob Decrypts:
    • Bob calculates mask: s = c₁ˣ mod 23 = 19⁶ mod 23 = 2.
    • Inverse of 2 mod 23: 2⁻¹ ≡ 12 (mod 23) (since 2 × 12 = 24 ≡ 1 mod 23).
    • Plaintext: m = (c₂ · s⁻¹) mod 23 = (14 · 12) mod 23 = 168 mod 23 = 7. ✓

4. Cryptanalysis & Hardness Comparison

The operational security of DLP cryptosystems is governed by the underlying group structure:

Group FamilyBest Known Classical AttackAsymptotic ComplexityNIST 128-Bit Key Requirement
Finite Field ℤp* (FFDHE / DSA) Index Calculus & General Number Field Sieve (NFS) Subexponential: L_p[1/3, c] = exp((c + o(1))(ln p)¹/³ (ln ln p)²/³) p ≥ 3072 bits (Subgroup q ≥ 256 bits)
Elliptic Curves E(𝔽p) (ECDH / ECDSA) Pollard's ρ / Baby-Step Giant-Step Exponential (Generic): O(√n) ≈ 2^{b/2} 256-bit curve (Curve25519, secp256r1)

Hardening & Implementation Guidelines

  • Safe Primes (Sophie Germain): When configuring finite field DH groups (e.g., RFC 3526 / RFC 7919 MODP groups), choose primes where p = 2q + 1 with q prime. This eliminates small subgroups vulnerable to the Pohlig-Hellman algorithm.
  • Subgroup Confinement Validation: Always validate incoming public keys: verify 1 < A < p − 1 and A^q ≡ 1 (mod p) to avoid small-subgroup confinement attacks.
  • Constant-Time Execution: Exponentiation ladders (Montgomery Ladder) must execute with fixed timing and power draw to prevent side-channel timing attacks (SPA/DPA).
  • Quantum Horizon: Polynomial-time resolution of both DLP and Integer Factorization via Shor's Algorithm on quantum hardware necessitates modern hybrid deployments integrating NIST Post-Quantum standards (ML-KEM-768 / ML-DSA).
