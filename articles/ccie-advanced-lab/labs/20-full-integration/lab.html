Key Concepts

Integration Architecture

This final lab runs all 20 protocols simultaneously on the full topology. The MPLS backbone (Labs 01-05) provides VPN services to CE sites. Dual DMVPN regions (Labs 06-08) connect branch offices through MPLS-attached PE routers. BGP route reflection (Lab 09) scales iBGP. Communities and prefix filtering (Labs 11-12) control policy. OSPF multi-area (Lab 13) and OSPFv3 (Lab 14) run concurrently. EIGRP named mode (Lab 15) handles DMVPN routing. MPLS-TE tunnels (Lab 16) steer core traffic. Multicast (Lab 17) runs over both MPLS and DMVPN. QoS (Lab 18) marks and queues traffic end-to-end. 6PE (Lab 19) extends IPv6 across the IPv4 MPLS backbone.

Troubleshooting Methodology

In a full-integration scenario, troubleshoot from bottom up: Layer 1/2 physical connectivity → OSPF adjacencies (IGP) → LDP sessions (MPLS) → BGP sessions (overlay) → VRF routing (VPN) → DMVPN NHRP (overlay tunnels) → EIGRP over tunnels (dynamic routing) → Application reachability. Use structured isolation: ping from PE Loopback to PE Loopback (tests MPLS core), then VRF ping PE-to-CE (tests VPN), then CE-to-CE (tests end-to-end VPN). Each layer confirms the one below is working.

Verification Checklist

Complete verification requires confirming each protocol independently before testing integration points. The checklist below covers all 20 routers across all protocol domains. Run each command systematically and record expected vs actual output. Document any discrepancies — in the CCIE lab exam, partial credit is awarded per verified protocol, so thorough verification maximizes the score even if one subsystem has issues.
