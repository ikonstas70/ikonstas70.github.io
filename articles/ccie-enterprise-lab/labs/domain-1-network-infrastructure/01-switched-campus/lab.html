Key Concepts

MST (Multiple Spanning Tree) maps multiple VLANs to a single STP instance, reducing CPU overhead compared to PVST+ which runs one instance per VLAN. MST instances share a common internal spanning tree (IST) for BPDU communication, with each region appearing as a single bridge to outside regions.

EtherChannel bundles physical links into one logical channel, providing bandwidth aggregation and link redundancy. LACP (802.3ad) is the standards-based protocol; active/active is preferred for fast negotiation. The load-balancing algorithm (src-dst-mac, src-dst-ip) determines per-flow link selection — change with 'port-channel load-balance'.

BPDUGuard disables a PortFast-enabled port if it receives any BPDU, protecting against accidental switch connections. Root Guard prevents a port from becoming root port, protecting the STP root election. Loop Guard prevents alternate/root ports from becoming designated if BPDUs stop (unidirectional link failure).

Common Mistakes & Troubleshooting

EtherChannel not forming

Verify both ends use same mode (LACP active/active or active/passive). Check 'show etherchannel summary' for (I) flag = incompatible config. Speed, duplex, and trunk config must match.

MST instances not converging

Verify region name, revision number, and VLAN-to-instance mapping match exactly on all switches. Any mismatch puts switches in different MST regions. Use 'show spanning-tree mst configuration digest' to compare.

BPDUGuard not triggering

Confirm PortFast is enabled first ('spanning-tree portfast'). BPDUGuard only works on PortFast-enabled ports. Check 'show spanning-tree interface Gix/x detail'.
